= Das Private-Cloud-Erlebnis mit VMware Cloud Foundation und ONTAP optimieren
:hardbreaks:

[role="lead"]
NetApp ONTAP integriert sich in VMware Cloud Foundation (VCF) und bietet eine einheitliche Speicherlösung, die Block-, Datei- und Objektprotokolle unterstützt. Die Mandantenfähigkeit von ONTAP ermöglicht es Unternehmen, Workloads zu konsolidieren und die Verwaltung zu vereinfachen, während gleichzeitig Datenverfügbarkeit und Datenschutz der Enterprise-Klasse bereitgestellt werden. Dieses Dokument bietet einen Überblick über VCF und darüber, wie NetApp ONTAP zur Erweiterung der Speicherfunktionen innerhalb einer VCF-Umgebung genutzt werden kann.



[[introduction]]
== Einführung

VCF ermöglicht Unternehmen die einfache Bereitstellung und Verwaltung einer privaten Cloud-Umgebung. Standardmäßig werden VM, Kubernetes, Container und Netzwerke als Service bereitgestellt und es besteht die Möglichkeit, weitere Dienste als Katalogelemente in einem Self-Service-Portal anzubieten. Durch die Nutzung von NetApp ONTAP als Speicherlösung innerhalb von VCF können Unternehmen mehr Flexibilität, Skalierbarkeit und Effizienz bei der Verwaltung ihrer Workloads erreichen.



[[introduction-to-netapp-ontap]]
== Einführung in NetApp ONTAP

NetApp ONTAP ist eine umfassende Datenmanagement-Software, die fortschrittliche Speicherfunktionen über eine breite Produktpalette hinweg bereitstellt. ONTAP ist als softwaredefinierter Speicher, als First-Party-Service über die großen Cloud-Anbieter und als Speicherbetriebssystem für NetApp ASA (Disaggregated for Block Optimized), AFX (Disaggregated for unstrukturierte Daten), AFF & FAS (Unified) Plattformen verfügbar. ONTAP bietet hohe Leistung und mit niedriger Latenz für verschiedene Anwendungsfälle, einschließlich VMware Virtualisierung, ohne Silos zu schaffen. Ähnlich wie eine VM auf Compute erstellt wurde, ermöglicht ONTAP die Erstellung von Storage Virtual Machines (SVMs), die zur Erstellung und Verwaltung von Speicherressourcen genutzt werden können. ONTAP bietet eine einheitliche Speicherlösung, die mehrere Protokolle unterstützt, darunter NFS, SMB, iSCSI, FC, NVMe/TCP, NVMe/FC und NVMe/RDMA. Diese Flexibilität ermöglicht es Unternehmen, Workloads zu konsolidieren und die Verwaltung zu vereinfachen, während gleichzeitig Datenverfügbarkeit und Datenschutz der Enterprise-Klasse bereitgestellt werden.



[[introduction-to-vmware-cloud-foundation]]
== Einführung in VMware Cloud Foundation

VMware Cloud Foundation (VCF) ermöglicht es Unternehmen, virtuelle private Clouds zu erstellen, in denen sie VMs, Kubernetes-Cluster, Container, Netzwerke und Speicher als Dienstleistung nutzen können, sei es für KI-Workloads, DevOps oder traditionelle VM-basierte Workloads.

VCF wird in neuen Umgebungen oder zur Erweiterung einer bestehenden vSphere Umgebung zu einer vollständigen privaten Cloud eingesetzt. Eine Gruppe von Compute-Hosts bildet einen vSphere Cluster, eine Gruppe von vSphere Clustern bildet eine VCF-Domäne, und eine Gruppe von VCF-Domänen bildet eine VCF-Instanz. Eine Flotte besteht aus einer oder mehreren VCF-Instanzen. VCF Private-Cloud-Umgebungen werden mit einer oder mehreren Flotten erstellt. Betrieb und Automatisierung erfolgen auf Flottenebene, während die VCF-Instanz die Einheit der Bereitstellung ist.

Ein vSphere Namespace wird verwendet, um Ressourcenlimits für Workloads festzulegen. Eine vSphere Zone ist eine Sammlung von vSphere Clustern, die genutzt werden kann, um Hochverfügbarkeit und Disaster Recovery-Funktionen für Workloads bereitzustellen, die in der Zone ausgeführt werden.

image:vmware-vcf-overview-components.png["VMware Cloud Foundation-Komponenten"]

In VCF Automation ist eine Region eine Sammlung von vSphere Zonen aus einer oder mehreren VCF-Domänen, die dieselbe NSX-Infrastruktur nutzen. Eine Organisation ist eine logische Gruppierung von Benutzern und Ressourcen aus einer oder mehreren Regionen. Die Organisation kann in mehrere Projekte unterteilt werden, von denen jedes über ein eigenes Transit Gateway und eine eigene externe Verbindung verfügt. Ein Projekt besitzt einen oder mehrere Namespaces und kann zur Isolation und Ressourcenzuweisung für die im Projekt ausgeführten Workloads genutzt werden.

Namensräume sind die grundlegende Einheit für die Ressourcenzuweisung innerhalb eines Projekts. Jeder Namensraum ist einer virtuellen privaten Cloud (VPC) zugeordnet und kann zur Isolation und Ressourcenzuweisung für im Namensraum ausgeführte Workloads verwendet werden.

Namespaces werden mit einer dedizierten VPC oder einer gemeinsam genutzten VPC erstellt. Eine dedizierte VPC ist eine VPC, die einem einzelnen Namespace zugeordnet ist, während eine gemeinsam genutzte VPC eine VPC ist, die von mehreren Namespaces verwendet werden kann. Subnetze werden innerhalb einer VPC erstellt, in der die Workloads bereitgestellt werden.

Der Speicherplatz wird durch Storage Policy Based Management (SPBM)-Richtlinien belegt, die in vCenter definiert sind. SPBM kann mit einem Satz von Regeln erstellt werden, die die Speicheranforderungen für eine Arbeitslast festlegen. Die Datenspeicher werden typischerweise getaggt und zur Erstellung von Speicherrichtlinien genutzt, die den spezifischen Anforderungen verschiedener Arbeitslasten entsprechen.

Workloads, die Affinitäts- und Anti-Affinitätsregeln erfordern, werden durch Infrastrukturrichtlinien verwaltet, die vCenter Compute-Richtlinien verwenden, um die Platzierung von Workloads auf bestimmten Hosts oder Clustern festzulegen. Infrastrukturrichtlinien können verwendet werden, um sicherzustellen, dass Workloads entsprechend ihren Anforderungen auf bestimmten Hosts oder Clustern platziert werden.



[[vcf-domains]]
== VCF-Domänen

Domänen sind ein grundlegendes Konstrukt innerhalb von VCF, das die Organisation von Ressourcen in eindeutige, unabhängige Gruppierungen ermöglicht.  Domänen helfen dabei, die Infrastruktur effektiver zu organisieren und sicherzustellen, dass die Ressourcen effizient genutzt werden.  Jede Domäne wird mit ihren eigenen Rechen-, Netzwerk- und Speicherelementen bereitgestellt.

image:vmware-vcf-overview-domains.png["VMware Cloud-Domänen"]

Es gibt zwei Haupttypen von Domänen mit VCF:

* *Managementdomäne* – Die Managementdomäne umfasst Komponenten, die für die Kernfunktionen der VCF-Umgebung verantwortlich sind. Die Komponenten übernehmen wichtige Aufgaben wie Ressourcenbereitstellung, Überwachung und Wartung und beinhalten Integrationen von Drittanbieter-Plug-ins wie NetApp ONTAP Tools für VMware. Managementdomänen können mithilfe der VCF Installer Appliance bereitgestellt werden, um die Einhaltung bewährter Verfahren sicherzustellen, oder eine bestehende vCenter Umgebung kann in eine VCF Managementdomäne umgewandelt werden.
* *Workload Domain* – Workload Domains sind Ressourcenpools, die einem spezifischen Betriebsbedarf, einer bestimmten Arbeitslast oder einer Organisation zugeordnet sind. Workload Domains lassen sich einfach über den OPS Manager bereitstellen und tragen so zur Automatisierung komplexer Aufgaben bei. In einer VCF-Umgebung können bis zu 24 Workload Domains bereitgestellt werden, wobei jede eine Einheit anwendungsbereiter Infrastruktur darstellt. Ob eine Workload Domain über eine eigene NSX-Infrastruktur verfügt oder eine bestehende Infrastruktur mitnutzt, hängt davon ab, ob es sich um eine Einzel- oder Mehrregionsbereitstellung handelt.




[[storage-with-vcf]]
== Speicherung mit VCF

Der von ihnen verbrauchte Speicherplatz ist für die Funktionalität von Domänen von zentraler Bedeutung.  Während VCF CPU-Core-basierte vSAN-Kapazität für hyperkonvergente Anwendungsfälle umfasst, unterstützt es auch eine breite Palette externer Speicherlösungen.  Diese Flexibilität ist entscheidend für Unternehmen, die erheblich in vorhandene Speicher-Arrays investiert haben oder Protokolle unterstützen müssen, die über die Möglichkeiten von vSAN hinausgehen.  VMware unterstützt mit VCF mehrere Speichertypen.

Es gibt zwei Hauptspeichertypen mit VCF:

* *Primärer Speicher* – Dieser Speichertyp wird automatisch im Rahmen der Tag-0-Bereitstellung einer neuen VCF-Domäne oder im Zuge der Konvergenz oder des Imports eines bestehenden vCenter bereitgestellt. Der VCF-Installer unterstützt VSAN, VMFS auf FC und NFS im Rahmen einer Greenfield-Bereitstellung, während andere unterstützte Speichertypen, einschließlich VMFS auf iSCSI und NVMe-oF, im Rahmen der Konvergenz oder des Imports eines bestehenden vCenter als primärer Speicher bereitgestellt werden können. ONTAP Tools für VMware vSphere kann nur für die Konvergenz oder den Import eines bestehenden vCenter verwendet werden, um primären Speicher für eine VCF-Domäne bereitzustellen. Jeder Datenspeicher, der im Rahmen einer zusätzlichen Clusterbereitstellung oder einer Domänenerweiterung erstellt wird, gilt als primärer Speicher. Der primäre Speicher dient zum Hosten der VCF-Verwaltungskomponenten, einschließlich vCenter, NSX Manager und SDDC Manager, sowie der in der Domäne ausgeführten Workloads.
* *Zusätzlicher Speicher* – Zusätzlicher Speicher sind alle Datenspeicher, die nach der ersten Bereitstellung einer VCF-Domäne oder der Konvergenz oder dem Import einer bestehenden vCenter-Umgebung bereitgestellt werden. Zusätzlicher Speicher kann mithilfe von ONTAP Tools für VMware vSphere erstellt werden, um Datenspeicher für eine VCF-Domäne bereitzustellen. Zusätzlicher Speicher wird erstellt, um zusätzlichen Kapazitätsbedarf, Leistungsanforderungen zu erfüllen oder um spezifische Workloads zu unterstützen, die unterschiedliche Speichereigenschaften erfordern. Zusätzlicher Speicher kann auch erstellt werden, um Stretch-Cluster für hohe Verfügbarkeit bereitzustellen.


*Unterstützt VCF-Speichertypen*

[cols="25%, 25%, 50%"]
|===


| *Domänentyp* | *Hauptspeicher* | *Zusätzlicher Speicher* 


| Verwaltungsdomäne | vSAN FC NFS 3 NFS 4.1 ^2^ iSCSI ^2^ NVMe/TCP ^2^ NVMe/FC ^2^ NVMe/RDMA ^2^ | vVols (FC, iSCSI oder NFS) ^1^ FC NFS 3 NFS 4.1 iSCSI NVMe/TCP NVMe/FC NVMe/RDMA 


| Workload-Domäne | vSAN vVols (FC, iSCSI oder NFS) ^1^ FC NFS 3 NFS 4.1 ^2^ iSCSI ^2^ NVMe/TCP ^2^ NVMe/FC ^2^ NVMe/RDMA ^2^ | vVols (FC, iSCSI oder NFS) ^1^ FC NFS 3 NFS 4.1 iSCSI NVMe/TCP NVMe/FC NVMe/RDMA 
|===

[[why-ontap-for-vcf]]
== Warum ONTAP für VCF

Neben Anwendungsfällen, die Investitionsschutz und Multiprotokollunterstützung beinhalten, gibt es viele weitere Gründe, die Vorteile externer gemeinsam genutzter Speicher innerhalb einer VCF-Workloaddomäne zu nutzen.  Es kann davon ausgegangen werden, dass der für eine Workload-Domäne bereitgestellte Speicher lediglich ein Repository zum Hosten von VMs und Containern ist.  Die Anforderungen der Organisation übersteigen jedoch häufig die Möglichkeiten der lizenzierten Kapazität und erfordern Unternehmensspeicher.  Der von ONTAP bereitgestellte Speicher, der Domänen innerhalb von VCF zugewiesen ist, lässt sich einfach bereitstellen und bietet eine zukunftssichere Shared-Storage-Lösung.

image:why-ontap-for-vmware-002.png["Warum ONTAP für VCF"]

Weitere Informationen zu den wichtigsten ONTAP Vorteilen für VMware VCF finden Sie unten unterlink:vmw-getting-started-overview.html#why-ontap-for-vmware["Warum ONTAP für VMware"] .

* Flexibilität ab dem ersten Tag und bei der Skalierung
* Lagern Sie Speicheraufgaben auf ONTAP aus
* Klassenbeste Speichereffizienz
* Datenverfügbarkeit auf Unternehmensniveau
* Effiziente Backup- und Wiederherstellungsvorgänge
* Ganzheitliche Geschäftskontinuitätsfunktionen

[[summary]]
== Zusammenfassung

ONTAP bietet eine Plattform, die alle Workload-Anforderungen erfüllt und maßgeschneiderte Blockspeicherlösungen sowie einheitliche Angebote bietet, um schnellere Ergebnisse für VMs und Anwendungen auf zuverlässige und sichere Weise zu ermöglichen.  ONTAP umfasst erweiterte Techniken zur Datenreduzierung und -verschiebung, um den Platzbedarf des Rechenzentrums zu minimieren und gleichzeitig eine Verfügbarkeit auf Unternehmensebene sicherzustellen, damit kritische Workloads online bleiben.  Darüber hinaus unterstützen AWS, Azure und Google im Rahmen ihrer VMware-in-the-Cloud-Angebote externen Speicher auf NetApp-Basis, um den vSAN-Speicher in Cloud-basierten VMware-Clustern zu verbessern.  Insgesamt ist NetApp aufgrund seiner überlegenen Funktionen eine effektivere Wahl für VMware Cloud Foundation-Bereitstellungen.
