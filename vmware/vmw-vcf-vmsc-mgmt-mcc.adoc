= Konfigurieren eines Stretch-Clusters für eine VCF-Verwaltungsdomäne mit MetroCluster
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
In diesem Anwendungsfall wird die Vorgehensweise zur Konfiguration eines Stretch-Clusters für die VMware Cloud Foundation (VCF) Management-Domäne mit ONTAP MetroCluster unter Verwendung von FC, iSCSI, NVMe-oF, NFSv3 oder NFSv4.1 als primärem Datenspeicher dargestellt. VCF bietet Flexibilität bei den Bereitstellungsoptionen entsprechend Ihren Anforderungen. Das VCF Installer Tool wird entweder zur Bereitstellung einer neuen VCF Management-Domäne oder zur Umwandlung einer bestehenden vSphere Umgebung in eine VCF Management-Domäne verwendet. In diesem Dokument liegt der Fokus auf dem MetroCluster Abschnitt, und es wird auf weitere Dokumentationen zu den einzelnen Bereitstellungsschritten verwiesen.

image:vmw-vcf-vmsc-mgmt-mcc-001.png["VCF-Verwaltungsdomäne mit vMSC, Breite=500"]



[[introduction]]
== Einführung

In dieser Lösung wird gezeigt, wie eine Stretched VCF Management Domain mit ONTAP MetroCluster als Principal Datastore implementiert werden kann. MetroCluster ermöglicht die Bereitstellung einer Hochverfügbarkeitslösung für alle Workloads, die auf dem ONTAP Cluster ausgeführt werden. Falls eine Hochverfügbarkeitslösung speziell für bestimmte Workloads erforderlich ist, kann SnapMirror active sync (SAN und NAS) verwendet werden. SnapMirror active sync (SAN) arbeitet auf Konsistenzgruppenebene, während SnapMirror active sync (NAS) auf SVM-Ebene arbeitet. Weitere Informationen finden sich unter link:vmw-vcf-vmsc-mgmt-smas.html["Konfiguration eines Stretch-Clusters für eine VCF-Verwaltungsdomäne mit SnapMirror Active Sync (SAN und NAS)"].



[[prerequisites]]
== Voraussetzungen

Dieses Szenario erfordert die folgenden Komponenten und Konfigurationen:

* Unterstützte ONTAP MetroCluster Konfiguration
* Storage Virtual Machine (SVM) mit bevorzugtem Speicherprotokoll konfiguriert.
* Zur Übertragung des Speicherdatenverkehrs wurde eine logische Schnittstelle (LIF) erstellt, die mit der SVM verknüpft ist.

[[deployment-steps-for-greenfield-vcf-management-domain-with-metrocluster]]
== Bereitstellungsschritte für eine neue VCF-Verwaltungsdomäne mit MetroCluster

Bei einer Greenfield-Bereitstellung (Neuinstallation ohne vorhandene VCF-Komponenten) wird das VCF Installer Tool zur Bereitstellung der Management-Domäne verwendet. VMFS auf FC und NFSv3 werden in diesem Szenario unterstützt.

Im Falle von VMFS auf FC siehe link:vmw-vcf-mgmt-principal-fc.html["VCF Management-Domäne mit FC-basiertem VMFS-Datenspeicher auf ONTAP als primärem Storage"]für weitere Informationen. Für NFSv3 siehe link:vmw-vcf-mgmt-principal-nfs.html["VCF Management-Domäne mit NFSv3 Datenspeicher auf ONTAP als primärem Storage"]für weitere Informationen.



[[deployment-steps-for-brownfield-vcf-management-domain-with-metrocluster]]
== Bereitstellungsschritte für die Brownfield VCF Managementdomäne mit MetroCluster

Bei einer Brownfield-Bereitstellung handelt es sich um ein Szenario, in dem Sie über eine bestehende vSphere-Umgebung verfügen und diese als VCF Managementdomäne zusammenführen möchten.

Für iSCSI, NVMe-oF und NFSv4.1 ist eine Einrichtung mit vCenter (vorzugsweise mit ONTAP tools) erforderlich, anschließend wird das VCF installer tool verwendet, um die Konvergenz in die Managementdomäne durchzuführen. Weitere Informationen finden sich unter link:vmw-vcf-mgmt-vmfs.html["Konvergenz von vCenter mit VMFS-Datenspeicher"] und link:vmw-vcf-mgmt-nfs.html["Konvergenz von vCenter mit NFS-Datenspeicher"].
