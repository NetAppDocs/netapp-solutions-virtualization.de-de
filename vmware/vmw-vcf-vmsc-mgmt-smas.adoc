= Konfiguration eines Stretch-Clusters für eine VCF-Verwaltungsdomäne mit SnapMirror Active Sync (SAN und NAS)
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
In diesem Anwendungsfall beschreiben wir das Verfahren zur Verwendung von ONTAP tools for VMware vSphere zum Konfigurieren eines Stretch-Clusters für eine VCF-Verwaltungsdomäne.  Dieses Verfahren umfasst die Bereitstellung von vSphere-Hosts und vCenter Server, die Installation von ONTAP Tools, den Schutz von Datenspeichern mit SnapMirror Active Sync, die Migration von VMs zu geschützten Datenspeichern und die Konfiguration von zusätzlichem Speicher.

image:vmw-vcf-vmsc-mgmt-smas-001.png["Stretch Cluster mit ONTAP für die VCF-Verwaltungsdomäne"]

Für SAN werden sowohl uniforme als auch nicht-uniforme gestreckte Clusterkonfigurationen unterstützt. Im Fall von NAS handelt es sich um eine Aktiv/Passiv-Konfiguration mit ONTAP 9.19.1.

[NOTE]
====
Die Host-Proximity-Einstellungen werden in Verbindung mit der Multipath-Konfiguration verwendet, um die optimale Pfadauswahl für den Speicherdatenverkehr sicherzustellen. Die Host-Proximity-Einstellungen werden bei SCSI auf der Initiatorgruppe und bei NVMe-oF auf dem Subsystem konfiguriert. Beispielsweise hat der Host in einer Uniform Host Access-Konfiguration Zugriff auf beide Speichersysteme im Stretched Cluster. In der Multipath-Konfiguration werden die optimalen und nicht optimalen Pfade anhand der Host-Proximity-Einstellungen konfiguriert.

====


[[scenario-overview]]
== Szenarioübersicht

Die Stretch-Cluster-Lösung kann im Standardcluster oder in einem zusätzlichen Cluster in VCF-Management- oder Workload-Domänen implementiert werden. ONTAP tools 10.6 unterstützt den Schutz von Datenspeichern mit SnapMirror active sync für VMFS-Datenspeicher über iSCSI- und FC-Protokolle. ONTAP unterstützt SnapMirror active sync für SAN (mit iSCSI, FC, NVMe-oF) und NAS (NFS v3 und NFSv4.1). Bei SAN-Protokollen erfolgt der Schutz auf Konsistenzgruppenebene, bei NAS auf SVM-Ebene. Das folgende Diagramm veranschaulicht die Stretch-Cluster-Lösung für eine VCF-Management-Domäne mit ONTAP tools für VMFS mit FC.

image:vmware-vcf-asa-mgmt-stretchcluster-002.png["Stretch Cluster mit ONTAP für die VCF-Verwaltungsdomäne"]

.Hauptspeicher in der Verwaltungsdomäne
[%collapsible%open]
====
. Die VCF Management-Domäne kann mit jedem unterstützten Protokoll bereitgestellt werden.
+
.. Für VMFS auf FC und NFSv3 wird das VCF Installer Tool direkt verwendet. Bei iSCSI, NVMe-oF und NFSv4.1 erfolgt die Einrichtung mit vCenter, anschließend wird das VCF Installer Tool zur Bereitstellung der Management-Domäne verwendet. Weitere Informationen finden sich unter link:vmw-vcf-migrate.html["VCF Management Domain Deployment mit iSCSI, NVMe-oF und NFSv4.1"]


. Bereitstellen von ONTAP tools for VMware vSphere
. SnapCenter -Plugin für VMware vSphere bereitstellen (optional)
. Der Datenspeicher wird geschützt.
+
.. Für iSCSI und FC werden ONTAP tools ab Version 10.6 zum Schutz der Datenspeicher verwendet. Im Fall von NVMe-oF und NFSv4.1 wird der System Manager zum Schutz der Datenspeicher genutzt. Zum Vergleich befindet sich unten eine Videodemonstration zu NVMe/TCP und NFS.




====
.Zusätzlicher Speicher in der Verwaltungsdomäne
[%collapsible%open]
====
Sobald die Managementdomäne eingerichtet und betriebsbereit ist, können mit ONTAP tools 10.6 oder höher zusätzliche Datenspeicher erstellt und mit SnapMirror active sync für iSCSI und FC geschützt werden. Für NVMe-oF und NFS dient das untenstehende Videodemonstrationsbeispiel als Referenz, da die Demonstration an einer Workload-Domäne durchgeführt wird, aber die gleichen Schritte auch für die Managementdomäne gelten.

====
