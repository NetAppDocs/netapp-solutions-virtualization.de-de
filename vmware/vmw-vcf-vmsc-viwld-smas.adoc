= Konfiguration eines Stretch-Clusters für eine Workload-Domäne mit SnapMirror active sync (SAN und NAS)
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
In diesem Anwendungsfall wird die Vorgehensweise zur Konfiguration eines Stretch-Clusters für eine Workload-Domäne unter Verwendung von SnapMirror active sync mit ONTAP tools for VMware vSphere dargestellt (ONTAP tools 10.6 unterstützt FC und iSCSI). ONTAP unterstützt SnapMirror active sync sowohl für SAN (mit iSCSI, Fibre Channel und NVMe over Fabrics) als auch für NAS (NFSv3 und NFSv4.1).

image:vmw-vcf-vmsc-viwld-smas-001.png["Stretch Cluster für VCF mit SnapMirror Active Sync"]

Für SAN werden sowohl uniforme als auch nicht-uniforme gestreckte Clusterkonfigurationen unterstützt. Im Fall von NAS handelt es sich um eine Aktiv/Passiv-Konfiguration mit ONTAP 9.19.1.

[NOTE]
====
Die Host-Proximity-Einstellungen werden in Verbindung mit der Multipath-Konfiguration verwendet, um die optimale Pfadauswahl für den Speicherdatenverkehr sicherzustellen. Die Host-Proximity-Einstellungen werden bei SCSI auf der Initiatorgruppe und bei NVMe-oF auf dem Subsystem konfiguriert. Beispielsweise hat der Host in einer Uniform Host Access-Konfiguration Zugriff auf beide Speichersysteme im Stretched Cluster. In der Multipath-Konfiguration werden die optimalen und nicht optimalen Pfade anhand der Host-Proximity-Einstellungen konfiguriert.

====


[[scenario-overview]]
== Szenarioübersicht

Die Datenspeicher in der VCF Workload-Domäne können mit SnapMirror active sync geschützt werden, um eine Stretch Cluster-Lösung bereitzustellen. Der Schutz erfolgt auf Datenspeicher-Ebene (Konsistenzgruppe) für SAN und auf SVM-Ebene für NAS.



[[prerequisites]]
== Voraussetzungen

.Hauptspeicher in der Workloaddomäne
[%collapsible%open]
====
Die Workload-Domäne kann entweder durch Import oder durch Erstellung mit dem VCF Ops Tool erstellt werden.

. Eine Workload-Domäne mit einem beliebigen unterstützten Protokoll erstellen.
. link:https://docs.netapp.com/us-en/ontap-tools-vmware-vsphere-10/configure/add-vcenter.html["Registrieren Sie das Workload-Domänen-vCenter beim ONTAP Tools-Manager, um das vCenter-Plugin bereitzustellen"]
. link:https://docs.netapp.com/us-en/ontap-tools-vmware-vsphere-10/configure/add-storage-backend.html["Registrieren Sie Speichersysteme auf ONTAP -Tools"]
. Für iSCSI- und FC-Datenspeicher siehe link:https://docs.netapp.com/us-en/ontap-tools-vmware-vsphere-10/protect/protect-multiple-ds.html["Der vSphere Datenspeicher wird mit ONTAP Tools geschützt"]
. Für NVMe-oF und NFS Datenspeicher zeigt das folgende Video die Schritte zum Schutz der Datenspeicher auf der Workload-Domäne mit SnapMirror active sync.


====
.Zusätzlicher Speicher in der Workloaddomäne
[%collapsible%open]
====
Sobald die Workload-Domäne eingerichtet und betriebsbereit ist, können mithilfe von ONTAP Tools zusätzliche Datenspeicher erstellt und geschützt werden. Weitere Informationen zu SnapMirror active sync finden sich unter https://docs.netapp.com/us-en/ontap/snapmirror-active-sync/index.html#benefits["Informationen zu ONTAP SnapMirror Active Sync"]


TIP: Mit ONTAP tools 10.6 und höher können die Datenspeicher auf der Workload-Domäne mit SnapMirror active sync geschützt werden. Die Schritte zum Schutz der Datenspeicher auf der Workload-Domäne mit SnapMirror active sync sind in der folgenden Videodemonstration zu sehen.

====
